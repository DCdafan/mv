# 技术架构

## 总览

```mermaid
flowchart LR
  subgraph 主进程 Main
    IPC[IPC 接口]
    Store[(项目 / 设置<br/>JSON)]
    Cache[(代理图缓存<br/>MVMediaCache)]
    Queue[导出队列]
    FF[FFmpeg<br/>合成音轨]
  end
  subgraph 编辑器窗口
    UI[React 界面<br/>Zustand 状态]
    Ana[照片分析<br/>MediaPipe]
    Beat[节拍分析<br/>Web Worker]
    Arr[自动编排]
    R1[WebGL 渲染器<br/>实时预览]
  end
  subgraph 导出窗口（隐藏）
    R2[WebGL 渲染器<br/>逐帧]
    Enc[WebCodecs<br/>H.264 硬件编码]
    Mux[mp4-muxer]
  end
  UI --> Ana --> Arr
  UI --> Beat --> Arr
  Arr --> R1
  UI <--> IPC
  IPC --> Store
  Ana --> Cache
  UI -- 加入队列 --> Queue
  Queue -- 打开 --> R2 --> Enc --> Mux -- 分块写盘 --> Queue
  Queue --> FF --> MP4[(成片 MP4)]
```

预览和导出用的是**同一个渲染器**（`engine/renderer.ts`），只是画布尺寸和纹理精度不同，所以预览看到什么，导出就是什么。

## 数据模型

项目是一个 JSON 文件（`src/shared/types.ts`）：

```
Project
├─ templateId / aspect / seed
├─ photos[]        原图路径、代理图、缩略图、分析结果（人脸、清晰度、哈希、焦点、问题标记）
├─ music           路径 + 分析结果（BPM、节拍、重拍、能量曲线、波形）
├─ musicOffset     从音乐第几秒开始
├─ scenes[]        场景序列
│   ├─ kind        intro / photo / outro
│   ├─ styleId     使用模板中的哪种版式
│   ├─ photos[]    每个槽位的照片
│   ├─ start / duration
│   ├─ transition  进入下一场景的转场与时长
│   ├─ focus       手动焦点
│   └─ texts       字幕覆盖
├─ meta            标题、副标题、日期、片尾寄语
└─ settings        节奏、时长模式、粒子开关、音量、淡出
```

模板不存进项目，项目只存 `templateId` 和 `styleId`。所以模板升级后，老项目打开就是新效果。

## 渲染引擎

`src/renderer/src/engine/`

### 一帧是怎么画出来的

1. 根据时间 `t` 找到当前场景；如果处在两个场景交界的转场窗口里，就同时找出前后两个场景
2. 每个场景画到自己的帧缓冲（FBO）里：背景 → 照片 / 形状 / 文字 / 装饰 / 粒子图层，依次叠加
3. 有转场时，用转场着色器把两个 FBO 合成一张
4. 叠加模板的全局粒子（花瓣、星光等）和影楼水印
5. 后期处理：暗角、胶片颗粒、漏光、片头片尾的黑场淡入淡出，输出到屏幕或导出画布

所有动画都是"时间的函数"，没有累积状态，所以可以跳到任意一帧直接渲染，导出时也能逐帧确定性地渲染。

### 图层

| 图层 | 说明 |
|---|---|
| `bg` | 纯色、线性 / 径向渐变、图案（纸纹、波点、网格、胶片孔）、照片模糊背景 |
| `photo` | 照片：cover 裁剪、推拉摇移、遮罩、边框、阴影、调色、分屏切片 |
| `shape` | 形状色块或描边（与照片共用遮罩） |
| `text` | Canvas2D 排版生成纹理：中文字体、字距、描边、阴影、金色渐变、逐字显现 |
| `decor` | 程序绘制的装饰：囍、灯笼、祥云、对戒、气球、学士帽、邮戳、胶带等 |
| `particles` | 粒子：花瓣、雪花、爱心、星光、光斑、气泡、彩纸、金粉、萤火 |

遮罩用 SDF（有向距离场）在片元着色器里计算：矩形、圆角、椭圆、圆形、爱心、拱门、菱形、六边形，边缘自带抗锯齿，边框和阴影也用同一个距离场。

### 动画

- 入场 / 出场：淡入、滑入、飞入、缩放、弹出、旋转、翻转、掉落、展开、逐字显现，可设延迟与缓动
- 循环：漂浮、呼吸、摇摆、旋转、脉冲
- 照片运镜：推近、拉远、左右 / 上下摇移。`auto` 模式根据照片和画框的比例选择（竖图放进横框时上下摇），推近时朝人脸焦点移动

### 转场

26 种，每种是一段 GLSL：叠化、闪白、闪黑、推入 ×4、擦除 ×3、圆形展开、爱心、菱形、时钟、百叶窗、方块、冲击变焦、穿越、梦幻、漩涡、水波、像素化、模糊溶解、燃烧、水墨、翻转、立方体、开门、旋转缩放、光晕、故障、缩放滑入。

### 粒子

每个粒子的位置、大小、旋转、透明度都由 `hash(粒子序号)` 和时间直接算出，不需要逐帧模拟。用 WebGL2 实例化绘制，一次 draw call 画完；发光类粒子用"预乘 alpha 为 0"的技巧实现叠加混合，不用切换混合模式。

### 纹理管理

- 照片纹理按需异步加载，LRU 淘汰；同时生成一张 96px 的模糊小图做模糊背景
- 预览加载 2048px 代理图；导出 2K 以上时直接读原图
- 文字和装饰纹理按内容缓存；字体加载完成后自动清缓存重画，避免出现回退字体

## 智能分析

### 节拍（`analysis/beat.ts`，运行在 Web Worker）

1. 解码并重采样到 22050Hz 单声道
2. STFT（1024 点，跳步 512），对数幅度谱的正向差分求和 → 起音强度曲线
3. 减去局部均值并标准化；轻微平滑后做自相关，结合 115 BPM 附近的先验估计速度
4. Ellis 动态规划节拍追踪，得到节拍时间
5. 4/4 拍：比较 4 种相位上的低频起音强度，确定小节第一拍（重拍）
6. RMS 能量曲线（0.25 秒一格，2 秒平滑），用于判断主歌 / 副歌
7. 可信度 = 拍点与反拍起音强度的对比；太低时改用固定节拍网格

单元测试用合成节拍（80～140 BPM）验证速度误差 < 4%、拍点误差 < 50ms。

### 照片（`analysis/photo.ts`）

| 指标 | 方法 |
|---|---|
| 人脸、闭眼 | MediaPipe Face Landmarker，blendshape `eyeBlinkLeft/Right` |
| 清晰度 | 512px 灰度图的拉普拉斯方差，与同批照片中位数比较 |
| 重复 | 9×8 dHash，汉明距离 ≤ 6 视为重复，保留评分高的 |
| 曝光 | 平均亮度与高光 / 暗部裁切比例 |
| 焦点 | 有人脸取人脸（偏上，眼睛位置）；否则取边缘能量重心 |
| 评分 | 清晰度、人脸、问题标记加权 |

## 自动编排（`arrange/arranger.ts`）

1. 跳过音乐开头的静音，建立节拍网格（超出音乐长度时按周期外推，音乐循环）
2. 片头：选一张评分高、方向与画布一致的照片
3. 正片：每一步看队列前几张照片，找出槽位方向能对上的版式（`match` 与画布同向、`cross` 反向），按权重随机挑选，并考虑：
   - 当前音乐能量是否在版式适合的范围
   - 避免连续重复同一版式
   - 节奏快时多图版式更常出现
4. 时长：每张照片的基础停留时间 × 版式系数 × 能量系数，取整到节拍，尽量对齐小节线
5. 转场：按模板权重随机，避免连续重复，时长以拍为单位且不超过场景的 60%
6. 字幕：支持字幕的版式按顺序分配模板文案
7. 片尾

同样的照片、模板、音乐和随机种子，编排结果完全一致；「换一换」就是换一个种子。

## 导出（`render-main.ts` + `main/exporter.ts`）

1. 主进程为每个任务打开一个隐藏窗口，把项目、品牌设置、导出参数交给它
2. 隐藏窗口创建导出分辨率的渲染器，加载全部字体
3. 逐帧：预加载照片 → 渲染 → `new VideoFrame(canvas)` → `VideoEncoder.encode`（优先硬件 H.264 High Profile，按分辨率和帧率选 Level）
4. `mp4-muxer` 流式封装，数据分块通过 IPC 写到主进程的临时文件，控制内存占用
5. 主进程用 FFmpeg 截取音乐、加淡入淡出与音量、编码 AAC，和视频流合并（视频不重新编码）
6. 一个任务完成后自动开始下一个，界面实时显示进度和渲染速度

## 安全

- 渲染进程开启 `contextIsolation`，只通过 preload 暴露有限 API
- 本地照片和音乐通过自定义 `mvfile://` 协议读取；界面文件通过 `app://` 协议提供，并检查路径不越出界面目录
- 页面设置了严格的 CSP（禁止 `eval`，只允许 WASM 编译）

## 踩过的坑

- **缓存目录不能叫 `cache`**：macOS 文件系统默认不区分大小写，`userData/cache` 和 Chromium 自己的 `Cache` 目录是同一个，会被 Chromium 清空
- **生产环境不能用 `file://` 加载界面**：MediaPipe 需要 `fetch` WASM 和模型文件，`file://` 下会失败，改用自定义 `app://` 协议
- **帧缓冲反馈回路**：往 FBO 画图时，如果这张 FBO 的纹理还绑在某个纹理单元上，WebGL 会报错，每个 pass 结束后需要解绑
- **字体异步加载**：先用回退字体画出来的文字纹理会被缓存，字体加载完要清缓存重画
- **自相关的倍频误判**：节拍周期不是整数帧时，自相关峰值会分散到相邻的两个延迟上，导致误判成半速，平滑起音曲线后解决
